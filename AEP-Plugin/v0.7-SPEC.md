# v0.7 — Configurable LED and PWM channels

## Background

v0.6.x hardcodes the electrolysis LED channel to `D` (in
`electropioreactor.py:_set_led_d`). The PWM (CO2 solenoid) channel is
already user-configurable via Pioreactor's `[PWM] N = relay` label
indirection, which the plugin reads through `config.get("PWM_reverse",
"relay")`. The LED side has no equivalent indirection.

Gerrit (Pioreactor team) flagged this on PR #16: assuming channels D and 4
are always free is fragile if the unit also runs other plugins or the
built-in jobs that take LED slots.

## Scope of v0.7

1. Make the electrolysis LED channel configurable via `config.ini`.
   Default to `D` for backwards compatibility with existing 0.6.x users.
2. Document the existing PWM-channel indirection in the README so users
   know they can pick channel 1, 2, 3, or 4 via the `[PWM] N = relay`
   label.
3. Update YAML descriptor descriptions to reference "the configured LED
   channel" / "the configured PWM channel" rather than D and 4
   specifically.
4. Validate the configured LED channel at job init: must be one of
   `A`, `B`, `C`, `D`. Refuse to start otherwise with a clear error.
5. Update `additional_config.ini` and `scripts/patch-config-ini.py` to
   write the new `led_channel` default.
6. Tests: parameterise the LED-channel-bearing tests so behaviour is
   verified for at least one non-default channel.

## Acceptance criteria

- Setting `[electropioreactor.config] led_channel = B` in
  `config.ini` causes `led_intensity({"B": ...})` to be called instead of
  `led_intensity({"D": ...})` on every electrolysis ramp.
- Invalid channel (e.g. `Z`) raises a clear `ValueError` at
  `__init__`, surfacing through Pioreactor's job-start error path.
- README has an "Hardware connections" section that documents both LED
  and PWM channel choice with `config.ini` snippets.
- Existing 0.6.x users on default config (channel D, PWM 4) see no
  behaviour change.

## Out of scope for v0.7

- Per-experiment overrides via `unit_config.ini` (already supported by
  the existing config loader for the four numeric settings; documenting
  the LED/PWM channel override there is a v0.7 stretch goal but not
  required).
- Runtime channel switching via the Advanced modal. Channels are
  hardware bindings; switching at runtime would require teardown and
  reinit of the LED/PWM. Not worth the complexity in v0.7.

## Implementation notes

- The PWM-channel reading pattern is already in
  `electropioreactor.py:89` —
  `config.get("PWM_reverse", "relay")`. Mirror that for the LED side via
  a new `[electropioreactor.config] led_channel` setting and a helper
  `_get_led_channel()` that reads + validates.
- `_set_led_d` becomes `_set_led(intensity)` and reads the cached
  channel from `self._led_channel` (set once in `__init__`).
- Tests in `tests/test_electropioreactor.py` should be parameterised
  with at least one non-D channel (e.g. `B`) plus one invalid channel.
