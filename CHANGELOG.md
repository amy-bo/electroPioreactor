## 2026-09-28

- [x] **Non-leading multiple-choice checks; steps split where a check came too late** — every step check in the AEP, MEP and BAEP guides was a yes/no question ("Did you move the shunt…?") that a builder in a hurry answers yes. Each is now an observational question ("Where is the HAT's shunt connector now?") with options worded alike, every wrong option something a rushed builder could have done and carrying its fix; the site spreads the correct option's position evenly. A check that could only be passed by undoing later work in the same step now ends the first half of a split step: the raft is checked before it is pressed together (`step-01`/`step-02`, all guides), the shunt before the vial holder covers it (AEP `step-03`/`step-04`), electrode polarity and depth before electrolysis runs (AEP `step-07`/`step-08`, MEP `step-05`/`step-06`), pump channels and the 12 V supply before calibration (AEP `step-09`/`step-10`, MEP `step-08`/`step-09`), the gas train before gas goes in (AEP `step-12`/`step-13`, MEP `step-10`/`step-11`) and the regulator pressure before the CO₂ flow is measured (AEP `step-15`/`step-16`). Files and ids are renumbered to match `order` (the loader requires id = filename stem, so renumbered steps have new URLs); links, bold step names, the MEP protocol page and the media shoot list follow. `<!-- VIDEO CUT -->` comments mark where each recording splits. The raft photo is recompressed (118 KB to 53 KB) and the page budget raised to 210 KB so every step page fits.

## 2026-09-22

- [x] **Offline route: wheels, other plugins, and the PWM 4 collision** — first run on real hardware (ed06) validated the card staging and the unit's own access point, and turned up three things. The image's venv is Python 3.13 with no setuptools, so building the plugin from source on the unit fails and it fell back to the plugins folder; `stage-sd-card.sh` now builds a wheel on the computer that has pip, and the installer prefers it. A third argument names other Pioreactor plugins to fetch as wheels at staging time - `pioreactor-precision-temperature-plugin` for an AEP0.2 with the temperature kit - and the installer does for them what `pio plugins install` does over the network: UI descriptors into `~/.pioreactor/plugins/ui/`, `additional_config.ini` merged without overwriting, `post_install.sh` run. And stock Pioreactor ships `[PWM] 4=waste`, so the config patcher refused on a fresh leader and `set -e` took the rest of the install with it; the patcher now explains that `waste` is a default rather than a wiring fact and takes `--force` (`EP_FORCE_PWM4=1` through the installer), and the installer carries on to the end and reports what needs dealing with instead of dying mid-way.
- [x] **Offline install route for a build site with no network** — the plugin install assumed a LAN and internet on the unit (`git clone` on the Pi), which fails wherever the Pioreactor cannot join a network. Added `AEP-Plugin/scripts/stage-sd-card.sh`, run on the Mac with the freshly imaged card still in the reader, which writes Pioreactor's `local_access_point` flag file (contents: the two-letter WiFi country code) and an `electropioreactor/` payload to the FAT boot partition, and `AEP-Plugin/scripts/install-from-card.sh`, run on the unit after first boot, which installs from `/boot/firmware/` with no network: pip from the staged source where it can build offline, otherwise Pioreactor's plugins-folder mechanism, then the UI descriptor, `config.ini` patch, `lighttpd` restart and the usual checks. The install itself cannot happen while the card is in the Mac — macOS mounts only the FAT partition and the plugin lands on the ext4 root — so the card stage is preparation and the unit's own access point (`pioreactor` / `raspberry`) is the way in. Documented in the plugin README with the ethernet-and-Internet-Sharing alternative that keeps the canonical instructions working, and referenced from guide step 4.
- [x] **Review findings filed as step TODOs** — the four issues raised while reviewing the guide now carry `<!-- TODO -->` comments next to the text each one concerns: the tool lists in `step-00` duplicating that step's frontmatter `tools:` block, `step-02` and `step-03` restating their own titles above the heading the site renders from them, the hard-coded step cross-references in `step-04`, `step-05` and `step-09`, and `step-11`'s bare `BoM.md` reference to a file outside `docs/`.
- [x] **Guide editing pass: shunt connector step, photographs restored, change notes collapsed** — the AEP0.1.1-to-AEP0.2 commentary was interleaved with the build instructions, the Docs&I split had replaced four photographs with migration placeholders and dropped a fifth outright, and the HAT's shunt connector was never mentioned anywhere in AEP0.1.1 or AEP0.2. Added `step-02` sub-step 2 (move the shunt to the position closest to the LED outputs while the HAT is bare, before the vial holder is mounted at sub-step 4; without it PWM channels 1 to 4 stay on the Pi's supply, the PWM 4 CO₂ solenoid will not drive, and any calibration made first is invalidated), renumbered that step's sub-steps 1 to 8 and added a check-before-you-calibrate note to `step-06`. Restored all six original photographs with reshoot TODOs, including the relay screenshot in `step-09` that still shows the old `pioreactor-relay-plugin` toggle. Folded the multi-sentence AEP0.1.1 comparisons into `<details>` boxes, keeping safety and anything that changes what the builder does visible. Procurement now names nutrient solution and inoculum as kit gaps, the electrode depth criterion is tops flush with the vial cap, and the electrolysis check is reworded.
