## 2026-09-22

- [x] **Offline route: wheels, other plugins, and the PWM 4 collision** — first run on real hardware (ed06) validated the card staging and the unit's own access point, and turned up three things. The image's venv is Python 3.13 with no setuptools, so building the plugin from source on the unit fails and it fell back to the plugins folder; `stage-sd-card.sh` now builds a wheel on the computer that has pip, and the installer prefers it. A third argument names other Pioreactor plugins to fetch as wheels at staging time - `pioreactor-precision-temperature-plugin` for an AEP0.2 with the temperature kit - and the installer does for them what `pio plugins install` does over the network: UI descriptors into `~/.pioreactor/plugins/ui/`, `additional_config.ini` merged without overwriting, `post_install.sh` run. And stock Pioreactor ships `[PWM] 4=waste`, so the config patcher refused on a fresh leader and `set -e` took the rest of the install with it; the patcher now explains that `waste` is a default rather than a wiring fact and takes `--force` (`EP_FORCE_PWM4=1` through the installer), and the installer carries on to the end and reports what needs dealing with instead of dying mid-way.
- [x] **Offline install route for a build site with no network** — the plugin install assumed a LAN and internet on the unit (`git clone` on the Pi), which fails wherever the Pioreactor cannot join a network. Added `AEP-Plugin/scripts/stage-sd-card.sh`, run on the Mac with the freshly imaged card still in the reader, which writes Pioreactor's `local_access_point` flag file (contents: the two-letter WiFi country code) and an `electropioreactor/` payload to the FAT boot partition, and `AEP-Plugin/scripts/install-from-card.sh`, run on the unit after first boot, which installs from `/boot/firmware/` with no network: pip from the staged source where it can build offline, otherwise Pioreactor's plugins-folder mechanism, then the UI descriptor, `config.ini` patch, `lighttpd` restart and the usual checks. The install itself cannot happen while the card is in the Mac — macOS mounts only the FAT partition and the plugin lands on the ext4 root — so the card stage is preparation and the unit's own access point (`pioreactor` / `raspberry`) is the way in. Documented in the plugin README with the ethernet-and-Internet-Sharing alternative that keeps the canonical instructions working, and referenced from guide step 4.
